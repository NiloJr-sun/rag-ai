# rag-ai
For my 2nd half of 2026 objective!

## Project layout

The empty file tree was generated by [`scripts/scaffold.sh`](scripts/scaffold.sh),
which is idempotent and safe to re-run on a fresh clone.

## Quick start

Install the tools, then run one command:

```bash
# macOS
brew install uv ollama libpq && brew install --cask docker
ollama serve                     # in its own terminal, or start the app

git clone <this repo> && cd rag-ai
make setup
```

`make setup` checks your tools, creates the virtualenv, pulls both Ollama
models, writes a `.env` pointed at a throwaway Postgres container, starts that
container with the schema applied, and ingests the sample document. It takes a
few minutes, almost all of it downloading the chat model.

Then:

```bash
make ask Q="how do I cook pasta?"   # answer with sources, from the terminal
make dev                            # API on http://127.0.0.1:8000/docs
make check                          # lint, types and tests -- what CI runs
```

If `make setup` stops, `make doctor` tells you which tool is missing.

### Using Supabase instead of the container

`make setup` defaults to a local container so nothing external is required.
To use a real Supabase project, edit `DATABASE_URL` in `.env` (Project
Settings → Database → Connection string), then apply the schema once:

```bash
psql "$DATABASE_URL" -f backend/migrations/0001_init.sql
make ingest
```

### What each piece needs

| you want to | you need |
|---|---|
| `make test` | nothing — 75 tests, all mocked |
| `make check` | nothing |
| `make test-all` | Docker |
| `make ingest`, `make ask`, `make dev` | Docker or Supabase, plus Ollama |

## Running it

Common tasks are wrapped in the [Makefile](Makefile) — `make` on its own
lists them:

```bash
make venv        # create .venv and install the backend
make dev         # API with auto-reload on :8000
make check       # everything CI runs: lint, types, tests
make db-up       # throwaway pgvector container, migration applied
make test-all    # unit tests plus the storage integration tests
make ingest      # ingest data/samples
make ask Q="how do I cook pasta?"
```

Every target calls `.venv/bin/` directly, so none of them need an activated
virtualenv.

Prerequisites: [Ollama](https://ollama.com), Python 3.12, Docker (for the
local database and the integration tests), and either a Supabase project or
the `pgvector/pgvector:pg16` container.

```bash
# models
ollama pull nomic-embed-text      # embeddings, 768 dimensions
ollama pull qwen2                 # chat

# environment
uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install -e "backend[dev]"

# database (once). DATABASE_URL is read from .env by app/config.py, so it
# does not need exporting in every terminal.
psql "$DATABASE_URL" -f backend/migrations/0001_init.sql

# ingest, then ask
python scripts/ingest.py data/samples
python scripts/ask.py "How does cosine similarity work?"
python scripts/ask.py                       # interactive, Ctrl-D to quit
```

`ingest.py` takes a file or a directory and accepts `--reset`, `--max-size`
and `--skip-failures`. `ask.py` accepts `--top-k` and `--show-chunks`.

### API

```bash
uvicorn app.api.main:app --reload
```

| route | purpose |
|---|---|
| `POST /documents` | upload a `.txt` or `.md` file; chunks, embeds and stores it |
| `POST /ask` | answer a question from the stored documents, with sources |
| `/docs` | interactive API documentation |
| `/openapi.json` | OpenAPI schema |
| `/health` | liveness; touches nothing |
| `/health/ready` | readiness; reports whether Postgres and Ollama are reachable |
| `/config` | effective settings, with no secret values |

```bash
curl -X POST localhost:8000/documents \
  -F "file=@data/samples/sample.txt" -F "max_size=500"

curl -X POST localhost:8000/ask \
  -H 'content-type: application/json' \
  -d '{"question": "How do I cook pasta?"}'
```

Uploading the same filename again replaces that document's chunks rather than
duplicating them. A question the documents cannot answer returns 200 with
`is_refusal: true` — declining is the correct outcome, not an error.

`API_HOST` and `API_PORT` are read from the environment; see
[.env.example](.env.example).

### Tests

```bash
pytest backend/tests          # unit tests; no database or Ollama needed
```

The storage integration tests insert and delete rows, so they skip unless
`TEST_DATABASE_URL` is set — deliberately a separate variable from
`DATABASE_URL`, which `app/config.py` loads from `.env` and which therefore
points at the database you actually work against. Use a throwaway one:

```bash
docker run -d --rm --name ragpg -e POSTGRES_PASSWORD=test \
  -p 55432:5432 pgvector/pgvector:pg16
psql postgresql://postgres:test@127.0.0.1:55432/postgres \
  -f backend/migrations/0001_init.sql
TEST_DATABASE_URL=postgresql://postgres:test@127.0.0.1:55432/postgres \
  pytest backend/tests
```
